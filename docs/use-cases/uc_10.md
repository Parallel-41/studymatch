# UC-10 — Complete the cold-start self-assessment

**Objective:** Let a student with little or no history describe their level per area, so they can be profiled from day one.  
**Primary actor(s):** Student  
**Capability area:** Cold start  
**Target sprint:** 2  
**Preconditions:** Student is signed in.  
**Postconditions:** Cold-start data stored; profile recalculated.  

## Main success scenario
1. System detects that the student has areas without evidence and invites them to the self-assessment (first sign-in or profile page).
2. Student rates each competency area from 0 to 100, with descriptions of what 25 / 50 / 75 / 100 mean.
3. Student submits.
4. System stores one `SelfAssessment` per area and recalculates the profile (UC-08).

## Alternative / exceptional flows
* **2a.** Student skips an area → that area keeps no cold-start data.
* **1a.** Student already did it → the form opens pre-filled; the new answers replace the old ones (R10).
* **3a.** Value outside 0–100 → rejected.

## Business rules / constraints
* **BR-10-1:** Self-assessment is self-reported, so its influence fades as evidence grows (α, ADR-0003 §3).
* **BR-10-2:** The latest self-assessment per area is used (R10).

## Domain concepts revealed
* `SelfAssessment`, `Level`, `CompetencyArea`
